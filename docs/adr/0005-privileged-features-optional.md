# ADR-0005: 特権が要る機能は任意の高速化として扱う

- **状態**: 承認済み
- **日付**: 2026-09-21
- **関連**: D2 (F2)、設計方針 P4

## 背景

アプリが停止している間のファイル移動を拾うには、OS の変更ジャーナルが要る。当初の設計では Windows の USN Change Journal を「停止中の変更も完全に追える」前提で置き、Linux には等価物がないという非対称な構図で書いていた。

調査の結果、この前提は 2 点で誤っていた。

1. **USN Journal の操作には Administrators 権限が必要**（[Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_read_usn_journal)）。ボリュームハンドル `\.\C:` を開く時点で昇格が要る。
2. **保持期間は約 1 週間分**。それより古いカーソルからは読み直せず、結局スキャンが要る。

これは「管理者 / root を要求しない」という方針と正面から衝突していた。

## 決定

Windows の USN Change Journal と Linux の `fanotify` を **同格の「任意の高速化機能」** として扱う。既定はどちらの OS でも差分スキャン。

| | 特権あり（完全・高速） | 特権なし（**既定**） |
| --- | --- | --- |
| Windows | USN Change Journal（要 Administrator） | 差分スキャン |
| Linux | `fanotify`（要 `CAP_SYS_ADMIN`） | 差分スキャン |

## 理由

- **設計方針 P4（劣化して動く）と整合する**。特権がなくても機能は失わず、速度と精度が落ちるだけ。
- **両 OS が対称になる**。当初は「Windows は完全、Linux は妥協」という非対称な設計だったが、実際には両方に「特権あり / なし」の 2 経路がある。対称な設計の方が単純で、trait も素直になる。
- **既定で管理者を要求しないことは、この種のツールでは信頼の前提**。ファイルシステムを監視するアプリが最初に昇格を求めたら、多くの人はそこで離脱する。

## 結果

- `ChangeJournal::capability()` が `Full` / `None` を返し、`None` の場合は差分スキャンにフォールバックする。
- `fo doctor` が、いま使える経路と、特権を与えたら何が改善するかを表示する。
- **USN の保持期間切れは特権があっても起こる**ので、差分スキャンの実装は Windows でも必須。特権経路があるからといって省略できない。
